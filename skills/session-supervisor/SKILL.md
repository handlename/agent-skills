# Session Supervisor

The body of this skill lives in the Obsidian plugin [handlename/obsidian-plugin-session-supervisor](https://github.com/handlename/obsidian-plugin-session-supervisor), which extracts it into the vault on every desktop where Obsidian runs. This file only tells you where to find it. Follow these rules before anything else.

1. Find the skill directory. `<dir>` is the supervisor directory (default `~/supervisor`). Read `vault` from `## Locations` in `<dir>/CLAUDE.md`; without it, the vault is `<dir>/vault`. The skill directory `<skill-dir>` is `<vault>/.obsidian/plugins/session-supervisor/skill`.
2. Read `<skill-dir>/SKILL.md` to the end before following it. It is too large for one Read: read it in parts with `offset` / `limit` until the range you read reaches its last line, and confirm that it did. Then follow it, with `<skill-dir>` as the skill's base directory (its `references/`, `scripts/state_tool.py`, and `assets/`).
3. After compaction, resume, or `/clear`, whenever the body's content is no longer in your context, repeat rule 2 before you act.
4. In a new directory where `<dir>/CLAUDE.md` does not exist yet, ask the user for the vault path first. Do not create `<dir>/CLAUDE.md` by hand: run `setup` from the extracted copy (`python3 "<skill-dir>/scripts/state_tool.py" setup --dir "<dir>"`), which creates it from its template, then write the answer as `vault` in its `## Locations` and run `setup` again. Proceed to the body after that, and do not ask for the vault again in the body's Vault interview. The first `setup` also creates `<dir>/vault/Supervisor.md`; whether to delete the leftover `<dir>/vault/` is the user's choice.
5. When `<skill-dir>/SKILL.md` does not exist, tell the user: "Install and enable `handlename/obsidian-plugin-session-supervisor` with BRAT, and open Obsidian on this machine." Then stop.
